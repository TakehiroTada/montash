**montash** は、AI（LLM）が人間のプロンプト指示を受けて **CLI コマンドだけで動画編集を完結させる**ための動画編集ソフトです。
名前は **montage**（モンタージュ＝素材を繋いで意味を作る、編集の本質）と **sh**（シェル）を合わせたものです。

## 誰のためのものか

montash が想定しているのは、次のような人です。

- **AI に動画を編集させたい人**。「最初の 3 秒を切って」「繋ぎ目を全部クロスフェードに」と言えば、AI が `montash` を実行して結果を報告してくれる状態を作りたい。
- **手順を再現したい人**。同じ編集を別の素材でもう一度行いたい、あるいは何をしたかを後から説明したい。すべての操作がコマンドとして残るので、ログがそのまま手順書になります。
- **ターミナルで完結させたい人**。SSH 先や CI の中など、GUI が使えない環境で動画を組み立てたい。

逆に、タイムラインをマウスでドラッグしながら感覚的に詰めていきたい人には向きません。
montash のブラウザ画面は**確認のための画面**であって、編集操作は CLI が担当します。

## 設計の考え方

### 1. CLI ファースト

すべての編集操作は `montash <サブコマンド>` で行います。GUI からの編集操作は提供しません。
コマンドが唯一の入口なので、人間・AI・Web 画面のどこから操作しても、起きることは同じです。

出力は人間可読と機械可読の両方を持ちます。`--json` を付ければ構造化された結果が返り、
失敗したときは `error.code` と `error.hint` が返るので、AI はヒントを読んで自分で直せます。

```bash
montash clip trim c2 --in +0.5 --ripple --json
```

### 2. 非破壊

**元素材を書き換える操作は存在しません。** 取り込んだファイルは読むだけです。

編集状態は `project.json` という 1 つの JSON ファイルに宣言的に保持されます。
「どの素材のどこからどこまでを、タイムラインのどこに置くか」が書いてあるだけで、
映像そのものはコピーされません。書き出し（`montash render`）のときに初めて実際のピクセルが生まれます。

### 3. 時間は整数フレーム

プロジェクトを作るときに fps を決めると、以降の時間はすべてその fps 基準の**整数フレーム**で保存されます。

29.97fps は `{ "num": 30000, "den": 1001 }` という有理数として保持されるため、
小数の丸め誤差が蓄積してカット位置が少しずつずれる、ということが起きません。
秒で指定した値は最寄りのフレームにスナップされ、そのことが `W_SNAPPED` として返ります。

詳しくは [プロジェクトファイル](/ja/reference/project-file/) を参照してください。

### 4. ffmpeg に委譲する

デコード・エンコード・フィルタ処理はすべて ffmpeg / ffprobe が行います。
montash がするのは「どういう ffmpeg コマンドを組み立てるか」の決定と、その結果の検証です。

書き出し後には `montash render verify` 相当の検証が走り、フレーム数・FPS・音声長・ストリーム構成が
意図通りかを確認します。「書き出せたが 1 フレーム足りない」を検出できるようにするためです。

### 5. 履歴は git のように

状態を変えるコマンドは、実行するたびに **op** として自動で記録されます。
区切りのいいところで `montash commit -m "..."` すると、連続する op に人間が読める意味が付きます。

```bash
montash status                       # 今どこにいるか、未コミットの操作は何か
montash log --ops                    # これまでのコミットと操作
montash checkout before-bgm          # タグを付けた時点へ戻る
montash undo                         # 直前の操作を取り消す
```

`checkout` や `undo` は履歴を消しません。分岐は DAG としてそのまま残り、`montash log --all` で辿れます。

### 6. Web の操作も CLI の発行

`montash serve` で立ち上がるブラウザ画面からの操作（履歴の移動、素材の取り込み、ラベル付けなど）も、
例外なく対応する `montash` コマンドを子プロセスとして実行します。
履歴には `actor: web` として記録されるので、AI は人間が Web で何をしたかを `montash log --ops` で把握できます。
