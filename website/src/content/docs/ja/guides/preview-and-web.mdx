montash の編集は CLI で行いますが、**確認はブラウザ**で行います。
`montash serve` でローカル Web アプリが立ち上がり、再生・シーク・タイムライン・履歴・素材管理ができます。

## プレビューを作る

ブラウザで再生するための MP4 を組み立てます。

```bash
montash preview build
montash preview status
```

```
preview: ready  built_at=2026-09-15T05:30:28.791Z
```

映像はフレーム境界で分割してセグメント単位にキャッシュされ、音声は 1 パスで作られます。
そのため、2 回目以降は**変更した部分だけ**が作り直されます。

```bash
montash preview build --from 10 --to 20      # この範囲だけ作り直す
montash preview build --force                # 最新でもすべて作り直す
montash preview build --audio-only           # 音声だけ作り直す
montash preview build --height 540           # 出力の高さを指定する
```

:::note[プレビューと書き出しの違い]
プレビューはプロキシ画質で、ラウドネス正規化は適用されません（`W_NORMALIZE_DEFERRED`）。
最終的な画質・音量は `montash render` で確認してください。
:::

## サーバを起動する

```bash
montash serve --open
```

既定で `http://127.0.0.1:7788` にバインドし、`--open` を付けると既定のブラウザで開きます。

| オプション | 既定値 | 内容 |
|-----------|-------|------|
| `--port` | `7788` | ポート番号（`0` でランダム） |
| `--host` | `127.0.0.1` | バインドアドレス。**ループバック以外を指定すると自動的に `--read-only` になる** |
| `--open` | `false` | 既定のブラウザで開く |
| `--read-only` | `false` | 書き込み（`POST /api/cli`）を無効にし、閲覧専用にする |
| `--watch` | `true` | `project.json` と履歴を監視する（`--no-watch` で無効） |
| `--auto-preview` | `true` | 変更を検知したらプレビューを自動で作り直す（`--no-auto-preview` で無効） |
| `--dev` | `false` | フロントエンドを HMR 付きで配信する（開発用） |

`--watch` が有効なら、AI や自分が CLI で編集するたびにブラウザが自動で更新されます。
**ブラウザを開いたまま CLI で編集する**のが想定している使い方です。

## 画面の構成

| 領域 | 内容 |
|------|------|
| **ヘッダー** | プロジェクト名、解像度、fps、タイムライン尺、クリップ数、HEAD の状態（現在の op・所属コミット・未コミット数）、WebSocket の接続状態、プレビューの状態（`ready` / `building 45%` / `stale`） |
| **プレビューペイン** | プロキシ画質の合成動画を再生する |
| **トランスポート / シークバー** | 現在位置を `HH:MM:SS.mmm` と `f:<frame>` の両方で表示する |
| **編集タイムラインビュー** | 上から `T*`（テキスト）→ `V*`（映像、配列の逆順）→ `A*`（音声）。クリップ ID・ラベル・波形・トランジション・ギャップを描画する |
| **右ペイン** | **Inspector**（選択した要素の詳細と、対応する CLI コマンド例）／ **Assets**（素材の一覧・検索・取り込み・ラベル・再リンク・プロキシ再生成）／ **History**（コミットと op） |
| **History タイムライン** | 画面下部に常設。クリックでその時点へ `checkout` できる |
| **ログペイン** | 実行されたコマンドと ffmpeg の出力 |

### キーボード操作

| キー | 動作 |
|------|------|
| `Space` | 再生 / 停止 |
| `←` / `→` | 1 フレーム移動 |
| `Shift` + `←` / `→` | 1 秒移動 |
| `J` / `K` / `L` | 逆再生 / 停止 / 再生 |
| `Home` / `End` | 先頭 / 末尾 |
| `I` / `O` | ループ区間の指定（表示のみ） |
| `[` / `]` | undo / redo |

:::tip[AI に位置を伝えるとき]
シークバーは現在位置を `f:<frame>` でも表示します。
「ここを切って」と AI に伝えるときは、この `f:` 表記をそのまま渡すのがいちばん正確です。
:::

## ブラウザからできること・できないこと

ブラウザは**確認と素材管理のための画面**です。タイムラインの編集操作は CLI の領分です。

**できること**

- プレビューの再生・シーク
- トラック・クリップ・トランジション・テロップ・ギャップの可視化
- History タイムラインの表示と、クリックによる任意時点への `checkout`
- 素材の一覧・検索・単体プレビュー・取り込み（ドラッグ＆ドロップのアップロード）・削除・ラベル付け・再リンク・プロキシ再生成
- テキスト素材の作成
- 選択した要素に対応する CLI コマンド例の表示とコピー

**できないこと（CLI で行う）**

- クリップのドラッグやトリムなどのタイムライン編集操作
- `project.json` の直接編集
- **コミットの作成**
- レンダーの開始（進捗の表示のみ）
- 素材ファイルそのものの編集

## Web の操作も履歴に残る

ブラウザからの操作は、すべて対応する `montash` コマンドを子プロセスとして実行します。

1. ブラウザが `POST /api/cli { "args": [...] }` を送る
2. サーバが**許可リスト**と照合し（許可外は 403 `E_WEB_COMMAND_NOT_ALLOWED`）、`--json --yes` を強制で付け、`MONTASH_ACTOR=web` を設定して `montash` を起動する
3. 履歴には `actor: web` の op として記録される

つまり、ブラウザで行ったことも `montash undo` / `montash checkout` で戻せますし、
AI は `montash log --ops` で「人間が Web で何をしたか」を把握できます。

既定で許可されているのは履歴移動（`checkout`、`undo`、`redo`、`tag`、`tag delete`、`revert`、`reset --hard`）・素材管理（`import`、`assets set|set-text|new-text|remove|relink`、`proxy build`）・補助（`preview build`、`validate`）です。
タイムライン編集系（`clip *`、`text *`、`render *`、`commit` など）は既定で許可されていません。

破壊的なフラグ（`--force`、`--overwrite` など）は確認なしでは 409 `E_CONFIRM_REQUIRED` になります。

:::caution[外部に公開しない]
既定では `127.0.0.1` にしかバインドしません。
`--host 0.0.0.0` を指定すると自動的に `--read-only` が強制されますが、
そもそもローカル以外に公開する用途は想定していません。
:::
