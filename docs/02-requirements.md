# 02. 要件定義

## 1. 前提条件（与件）

| ID | 前提 | 出典 |
|----|------|------|
| P-1 | 動画編集作業は人間が AI にプロンプト指示し、AI が CLI でアプリを操作する。**全処理は CLI コマンドで行う** | 要件 |
| P-2 | Windows WSL / Linux / macOS の **bash** で動作する | 要件 |
| P-3 | プレビュー画面・シークバー・タイムラインは **Web アプリ** で提供する | 要件 |
| P-4 | エンコードは **ffmpeg** を利用する | 要件 |

### 前提から導かれる設計上の決定

| 決定 | 理由 |
|------|------|
| Web アプリからの状態変更は **すべて CLI コマンドの発行として実行**する（`POST /api/cli` → `montash ...`） | P-1「全処理は CLI」を守りつつ、履歴の移動と素材管理を Web から行えるようにするため。タイムライン編集（ドラッグ等）は Web に持たない |
| CLI 出力は `--json` を全コマンドで提供 | AI が結果を解釈して次の指示に繋げるため |
| 実装はフル TypeScript、ランタイム／パッケージマネージャは **Bun 1.2+**（`bun build --compile` で単一バイナリ配布） | P-2 の 3 OS で同一コードが動き、`Bun.serve` で Web サーバも同居できる。詳細は 08 / 12 章 |
| ffmpeg はシステムの `PATH` 上のものを使う（`--ffmpeg-path` で上書き可）。導入は `scripts/install-deps.sh` が OS 別に行う | P-4。同梱は配布サイズ・ライセンス面で後回し |
| パスは POSIX 形式のみ扱う（WSL では `/mnt/c/...`） | P-2。Windows ネイティブパスは対象外 |

## 2. 利用者とユースケース

### 利用者

| 役割 | 人物像 | この製品に対する接点 |
|------|--------|----------------------|
| 編集ディレクター（人間） | 動画の完成イメージを持ち、判断する。CLI は打たない | プロンプトで AI に指示、ブラウザで確認 |
| オペレーター（AI） | 指示をコマンド列に翻訳し実行する | `montash` CLI |
| 開発者 | 本ソフトを開発・拡張する | ソース、テスト、ドキュメント |

### 代表的ユースケース

- UC-1: 撮影素材数本をカット・結合してテロップを入れ、SNS 向けに書き出す
- UC-2: 長尺の収録から不要部分を取り除き、BGM を付けてアーカイブ用に書き出す
- UC-3: 既存プロジェクトの一部（テロップ文言、BGM 音量）だけ修正して再書き出し
- UC-4: 複数解像度・複数フォーマットで一括書き出し
- UC-5: 人間がプレビューを見て「ここのカットを 0.5 秒後ろに」と口頭指示 → AI が調整 → 再確認

## 4. 非機能要件

| ID | 分類 | 要件 |
|----|------|------|
| N-1 | 可搬性 | WSL2(Ubuntu 22.04+) / Ubuntu 22.04+ / macOS 12+ の bash で同一コマンドが動作する。CI で 3 環境をテストする |
| N-2 | 依存 | 実行時依存は ffmpeg/ffprobe と Bun のみ（コンパイル済みバイナリでは ffmpeg/ffprobe のみ）。ffmpeg は **4.4 以上で必須機能（libx264 / aac / xfade / concat / overlay / loudnorm / sidechaincompress）を持つビルド**を要件とし、6.0 以上・libass 入りを推奨（機能検出で判定。ADR-15）。ネイティブビルドが必要な npm パッケージを避ける。非 npm 依存は `scripts/install-deps.sh` で WSL / Linux / macOS に導入できる（Linux/WSL は sudo 不要の static ビルド） |
| N-3 | 性能（CLI） | 状態操作コマンド（add/move/trim 等）は 200ms 以内に完了する（ffmpeg 呼び出しを伴わない） |
| N-4 | 性能（プレビュー） | 10 分・10 クリップ程度のタイムラインのプロキシプレビュー生成が 1 分以内（プロキシ 640x360 前提、CPU 4 コア） |
| N-5 | 性能（レンダー） | ffmpeg のネイティブ速度を大きく損なわない（余分な中間ファイル生成を避ける、または明示的に選択させる） |
| N-6 | 安全性 | 元素材への書き込みを一切行わない。出力先が既存ファイルの場合は `--overwrite` なしでは失敗する |
| N-7 | 再現性 | `project.json` と素材があれば、同じ ffmpeg バージョンで同一の出力が得られる |
| N-8 | 観測性 | `--verbose` で実行した ffmpeg コマンドを全て記録。`.montash/logs/` にログを残す |
| N-9 | 互換性 | `project.json` にスキーマバージョンを持ち、旧バージョンの自動マイグレーションを提供する |
| N-10 | セキュリティ | Web サーバは既定で `127.0.0.1` にのみバインド。`--host 0.0.0.0` は明示指定時のみ（その際 `--read-only` を推奨）。Web からの CLI 発行は許可リスト制、引数は配列で spawn しシェルを経由しない。アップロードはプロジェクト配下に限定しファイル名をサニタイズ。パス指定はプロジェクトルート外を拒否（`--allow-outside` で許可） |
| N-13 | 監査性 | すべての状態変更は op として追記専用ログに残り、actor（ai/human/web）と実行引数が復元できる。`history verify` で整合性を検証できる |
| N-14 | フレーム精度 | タイムライン上のすべての時間はプロジェクト fps の整数フレームで保持し、カット点・トランジション・テキストの表示区間はレンダー結果で 1 フレームもずれない（`ffprobe -count_frames` によるゴールデンテストで保証）。音声位置の誤差は 1 サンプル未満 |
| N-11 | 国際化 | ファイル名・テロップの日本語（マルチバイト）を正しく扱う。drawtext のフォント指定でフォールバックを持つ |
| N-12 | テスト | 各作業手順（W-xx）を E2E スクリプトとして CI で実行する |

## 5. スコープ外（明示）

- GUI（Web 含む）からの **タイムライン編集操作**（クリップのドラッグ＆ドロップ、トリムハンドル等）。Web からの操作は履歴移動と素材管理に限定し、いずれも CLI 発行として実装する
- リアルタイム（フレーム単位レイテンシ）の再生エンジン。プレビューはプロキシの事前生成方式
- モーショングラフィックス（After Effects 相当）、3D、パーティクル
- クラウド連携、共同編集
- Windows ネイティブ（PowerShell / cmd）での動作保証
- 音声認識による自動字幕生成（外部ツールの SRT を取り込む形で対応）

## 6. 制約と前提の再確認

- ffmpeg の機能差（ビルドオプション：libx264、libfreetype、libass 等）で一部機能が使えない場合、`montash doctor` で検出し、該当コマンドは明確なエラーを返す。
- WSL2 ではブラウザ表示に Windows 側ブラウザを使う（`wslview` / `explorer.exe` 経由で `http://localhost:PORT` を開く）。ファイル監視は inotify が使えるため WSL2 の ext4 上での運用を推奨し、`/mnt/c` 配下はポーリングにフォールバックする。
